# Movie Picks v2 — Real movie data + streaming-style UX — Design

**Date:** 2026-10-15
**Builds on:** `2026-10-15-movie-recommendation-design.md` (architecture, model, AWS unchanged)

## Why

v1 works but feels like a prototype: generated placeholder posters, no way to
learn about a movie, a name prompt that blocks everything, and one long page.
v2 makes it look and feel like a streaming app so it demos well.

### Success criteria

- First-time visitor reaches personalised picks in under a minute with no
  typing: tap 3+ movies they love → home is personalised.
- Real posters/backdrops for movies TMDB knows; generated genre poster as
  fallback for the rest (and when no TMDB data has been fetched).
- Every movie has a details page reachable by URL (`#/movie/<id>`), with
  browser back/forward working.
- The TMDB key is only used offline; it never reaches the browser, Lambda, or
  git.
- No change to AWS infrastructure.

### Non-goals

- Accounts/login/names. Identity is an anonymous random id per browser.
- Trailers, streaming availability, half-star ratings.
- A frontend build step or framework.

## 1. Movie metadata from TMDB (offline)

- **`enrich.py`**: reads `data/ml-latest-small/links.csv` (MovieLens id →
  TMDB id) and calls `GET https://api.themoviedb.org/3/movie/{tmdbId}?append_to_response=credits`.
- **Key**: `TMDB_API_KEY` from the environment or a git-ignored `.env`.
  Accepts either the v3 "API Key" (sent as `api_key` query param) or the v4
  "Read Access Token" (starts with `eyJ`, sent as `Authorization: Bearer`).
- **Output**: `data/tmdb.jsonl`, one line per MovieLens movie:
  `{"movieId", "poster", "backdrop", "overview", "tagline", "runtime", "director", "cast": [≤5 names]}`
  where `poster`/`backdrop` are TMDB image *paths* (e.g. `/abc.jpg`) or null.
  Movies TMDB doesn't know (404) are recorded with all fields null so reruns
  skip them.
- **Resumable**: already-present movie ids are skipped; results are appended
  as they arrive. 8 worker threads; HTTP 429 → wait `Retry-After` (default 2 s)
  and retry; other errors → retry up to 3 times, then skip (not recorded, so a
  rerun retries it).
- **`train.py`** merges `data/tmdb.jsonl` (if present) into each model movie
  under the same keys. Missing file → those keys absent; everything still works.
- Model also gains `avg` (MovieLens mean rating, 1 decimal) per movie.

## 2. Backend changes

- Movie summaries (all list endpoints) gain `poster`: full URL
  `https://image.tmdb.org/t/p/w342<path>` or `null`.
- **`GET /api/movies/{id}`** → summary + `backdrop` (`…/w1280<path>` or null),
  `overview`, `tagline`, `runtime`, `director`, `cast`, `avg`, `count`
  (unknown TMDB fields → null / []). 404 if unknown movie.
- **`DELETE /api/users/{user}/ratings/{movie_id}`** → 204; deleting a rating
  that doesn't exist is also 204.
- User id rule unchanged (`^[A-Za-z0-9_-]{1,40}$`); the frontend uses a
  `crypto.randomUUID()` (36 chars) stored in `localStorage`.

## 3. Frontend

Plain HTML + ES modules, hash routing, served as static files (S3 locally via
uvicorn as before).

```
frontend/
  index.html  style.css  config.js
  js/ api.js  router.js  user.js  ui.js (poster card, row, stars, toast, skeleton)
      views/ welcome.js  home.js  movie.js  search.js  ratings.js
      main.js
```

**Top bar** (all pages except welcome): logo (→ home), search input,
"My ratings (n)".

**Routes**

| Route | Screen |
|---|---|
| `#/welcome` | Shown automatically when the user has < 3 positive ratings and hasn't skipped. Grid of ~40 popular posters; tap toggles "love it" (= 5★). Counter "Pick 3 or more". "Continue" enabled at 3; "Skip" link. |
| `#/` | Hero: backdrop + title + meta + tagline/overview of the #1 pick, "View details". Rows: "Top picks for you" (recommendations), up to 3 "Because you liked X" rows (similar to the user's highest-rated movies, rated ones removed), "Popular on Movie Picks". |
| `#/movie/<id>` | Backdrop header, poster, title, year · runtime · genres, tagline, overview, director, cast, "4.1 average from 218 MovieLens ratings", **Your rating** (5 large stars + "Remove rating"), "More like this" row. |
| `#/search?q=` | Poster grid of results, updated as you type (debounced 250 ms) from the top-bar input. Empty state explains what to type. |
| `#/ratings` | Grid of rated movies with editable stars and remove; empty state links to welcome; "Start over" (confirm → new random id, back to welcome). |

**Interaction details**

- Poster card: poster image (lazy-loaded, fixed 2:3 box so no layout jump),
  falls back to the generated genre poster on missing/failed image; title and
  year under it; whole card links to the details page.
- Rows scroll horizontally with scroll-snap; ‹ › buttons on desktop.
- Rating anywhere → toast "Rated Alien 5/5 — picks updated" (or "Removed
  rating for Alien"); home data refreshes on next visit to home.
- Loading: skeleton cards/rows; errors: inline message with a "Try again"
  button.
- Accessible: real links/buttons, visible focus, star group labelled, reduced
  motion respected, works at 360 px width with no horizontal page scroll.
- Footer: "Movie data and images from TMDB. This product uses the TMDB API but
  is not endorsed or certified by TMDB." + MovieLens credit.

**Visual direction**: dark theme suits poster-heavy browsing (posters pop on a
dark background) — deep blue-violet ink `#12111C` base, raised surfaces
`#1C1A2B`, text `#ECEAF5`, muted `#9C98B8`, star gold `#F2B705`, focus/accent
`#7FB4FF`. Big Shoulders Display for titles, Instrument Sans for text
(carried over from v1). Light mode not required.

## Testing

- `tests/test_enrich.py`: parse TMDB response (director from crew, top-5 cast,
  null-safe), 404 → null record, resume skips existing ids, Bearer vs api_key
  auth selection — with a fake HTTP function, no network.
- `tests/test_train.py`: merges tmdb.jsonl fields; `avg` computed; works
  without tmdb file.
- `tests/test_recommender.py` / `tests/test_api.py`: `poster` URLs in
  summaries, `GET /api/movies/{id}` (full + missing-TMDB + 404), DELETE rating.
- Frontend: scripted headless-Chromium walkthrough (welcome → pick 3 → home →
  details → rate → ratings → remove → search) at 1280 px and 390 px, asserting
  no console errors and no horizontal overflow, with screenshots reviewed.
