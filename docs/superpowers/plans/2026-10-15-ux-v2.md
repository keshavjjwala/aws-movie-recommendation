# Movie Picks v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** TMDB metadata (posters, details) fetched offline + streaming-style frontend with details pages and anonymous users.

**Architecture:** `enrich.py` → `data/tmdb.jsonl` → merged by `train.py` into the model; API exposes poster URLs, a details endpoint and rating deletion; frontend rewritten as ES modules with hash routing.

**Tech Stack:** unchanged (Python 3.12, FastAPI, boto3, pandas/sklearn offline; vanilla JS ES modules). TMDB HTTP via `urllib` (no new deps).

**Spec:** `docs/superpowers/specs/2026-10-15-ux-v2-design.md`

## Global Constraints

- TMDB key only in env/`.env` (git-ignored); never in model, frontend, Lambda.
- Poster URL `https://image.tmdb.org/t/p/w342<path>`, backdrop `https://image.tmdb.org/t/p/w1280<path>`.
- tmdb.jsonl record keys: movieId, poster, backdrop, overview, tagline, runtime, director, cast (≤5).
- User ids: `crypto.randomUUID()` in localStorage, pattern unchanged.
- No new runtime Python deps; no frontend build step.

## Review Focus

1. TMDB 429 rate limiting → waits and retries, does not drop the movie. Test in Task 1.
2. Movie without tmdbId / TMDB 404 → details endpoint returns nulls, UI shows generated poster. Tests in Tasks 1, 3; UI in Task 4.
3. Poster image fails to load (offline, 404) → falls back to generated poster. Task 4 walkthrough (blocked image host).
4. Deleting a rating that doesn't exist → 204, not 500. Test in Task 3.
5. Interrupted enrich run → rerun resumes without duplicates. Test in Task 1.
